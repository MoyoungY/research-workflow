# 实验设计、复现与运行

## 设计一项能执行的实验

从你给的研究问题或假设出发。已有项目先读 `experiment/evaluation.md`、相关的复现报告和已有版本；对齐数据切分、指标定义和单位。把方案写在 `experiment/<version>/plan.md`。如果本次只要设计，到方案就结束。如果已明确要求设计并运行，按给定的范围继续执行。

| 方案内容 | 要写清楚的约定 |
|---|---|
| 要检验什么 | 你的假设、可观察的预测、能够区分两种解释的对照 |
| 怎样保证可比 | 数据来源、版本、切分单位、处理代码；对照组和处理组各改什么、共同固定什么 |
| 怎样测 | 主指标、方向与单位、计算入口；配对种子和重复次数，或确定性任务为何只需一次 |
| 怎样运行 | 每组的配置、入口和参数、种子、输出；小样本检查与正式实验各需的设备、预计时长和资源上限 |
| 怎样读结果 | 哪些数值差异能回答这个问题，哪些情况仍无法区分解释；待你决定的取舍单列 |

例如你问「提升是否来自更多训练步数」，可以列出旧方法和新方法各自在相同步数下的配对对照；如果预算允许，再增加两种方法各自的长步数条件。两种方法共用数据、种子和评价脚本，结果表同时列绝对指标与配对差。方案中把推算的资源用量标为估计。

## 复现与运行

复现时从论文或官方代码找到目标表格、版本和参考命令；记录实际数据、依赖、配置、种子、原文数值及自测数值。写进 `reproduction/<method>/report.md`，链接到运行目录。遇到无法取得的数据或版本时说明具体差异。

按要求实现或复用真实项目入口，把与结果对应的脚本、配置和数据版本保存在项目里。先验证小样本经过的预处理、指标计算和输出，再按方案运行对照。技术故障可以在原范围内修复并重试；如果修复会改变切分、指标、实验变量或算力预算，写明影响，交给你决定。

从研究项目根目录启动本地命令。示例中的 `$SKILL_DIR` 指这个 skill 的安装目录，训练入口和参数换成项目自己的。每个实验条件、种子和重试都得到独立目录。

```sh
bun "$SKILL_DIR/scripts/run-experiment.ts" v1_steps baseline-seed7 -- bun experiment/v1_steps/train.ts --method baseline --steps 100 --seed 7
```

脚本逐项传递命令参数；工作目录保持项目根目录。第一行输出是本次 `experiment/<version>/runs/<label>-<unique>/` 的绝对路径。运行入口可通过环境变量 `RESEARCH_RUN_DIR` 写入本次的 `metrics.json`、图或检查点。既有程序可使用自身的输出参数，给每次运行独立路径，并在汇总前将真实指标复制到对应 run 或链接原始产物。命令参数会原样入档，认证信息通过程序原有的安全配置提供。

| 运行证据 | 如何使用 |
|---|---|
| `run.json` | 记录原始参数数组、工作目录、开始和结束时间、退出状态及运行期间产生的指标路径 |
| `stdout.log`、`stderr.log` | 调试失败时从对应 run 读取。长任务可用 `tail -f` 查看进度 |
| `metrics.json` 或程序自有结果 | 核对预定指标、样本数、条件和种子。退出码为零仅证明程序正常退出 |

本地运行器负责前台命令的生命周期。已有授权的远端或队列任务沿用项目原有入口，记录作业 ID，取得调度器最终状态、日志和指标后再记为完成。恢复旧会话时，如果记录仍为 `running` 或 `starting`，先核对进程或作业及产物；只有启动记录的任务标为状态待核实。

## 汇总与交接

按课题的标准化测评协议生成版本级交付。原版模板约定在 `experiment/<版本名>/` 保存汇总的 `metrics.json`、主图、分维度图和含固定 5–10 条样例的 `failure_cases.md`；样例沿用前一版的固定集合。每次运行的原始指标另存于对应的 `runs/` 子目录。研究者已填写的协议决定实际指标、文件名和比较口径。缺失测评所需的数据时，记录缺项及其影响。

从原始结果中提取每组、每个种子的实际数值；多种子给出有效样本数、均值和适用的离散程度，少于两次时不报样本标准差。失败、缺失、只跑了小样本的条目分别标明。按 `experiment/results.md` 现有列追加一条版本记录，链接方案和原始运行，保留失败版本与作废原因。每个窗口结束前按已有 `handoff.md` 交接，注明证据位置和下一窗口要做的事。观察到的差异与可能的解释分开记录，研究方向和论文主张由你确定。
